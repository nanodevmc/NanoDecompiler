# NanoDecompiler telemetry relay

Мини-сервер: принимает отчёты об ошибках от NanoDecompiler (`POST /report`)
и пересылает их тебе в Telegram — коротким текстовым сообщением-summary +
файлом с полным контекстом каждого отката на байткод (10 строк до, сам
байткод, 10 строк после — именно в таком порядке для каждого случая).

Без npm-зависимостей — только Node.js 18+ (нужен встроенный `fetch`).

## Установка

1. Скопировать `config.example.json` в `config.json`, заполнить:
   - `botToken` — токен бота от [@BotFather](https://t.me/BotFather);
   - `chatId` — твой личный chat id (см. ниже, как узнать);
   - `port` — на каком порту слушать (по умолчанию 8787);
   - `host` — на каком адресе слушать (по умолчанию `0.0.0.0`; за
     TLS-прокси ставьте `127.0.0.1`);
   - `reportSecret` — необязательно: если задать, клиент должен присылать
     тот же секрет в заголовке `X-Report-Secret` (клиент берёт его из
     переменной окружения `NANO_TELEMETRY_SECRET`), иначе сервер отклонит
     запрос. Пусто — сервер принимает любой `POST /report` без проверки;
   - `rateLimitPerHour` — сколько отчётов в час принимать с одного IP
     (по умолчанию 30, 0 — без ограничения);
   - `trustProxy` — `true`, если сервер стоит за обратным прокси: тогда
     IP клиента берётся из последнего значения `X-Forwarded-For`.

   Вместо `config.json` можно задать переменные окружения
   `TG_BOT_TOKEN` / `TG_CHAT_ID` / `PORT` / `HOST` / `REPORT_SECRET` /
   `RATE_LIMIT_PER_HOUR` / `TRUST_PROXY` — они в приоритете над файлом.

   `config.json` содержит токен бота и **не должен попадать в git**
   (он добавлен в `.gitignore`).

2. Запуск:
   ```bash
   node server.js
   ```

3. Клиент NanoDecompiler берёт адрес из переменной окружения
   `NANO_TELEMETRY_URL` (иначе — адрес по умолчанию, зашитый в сборку):
   `https://<домен-сервера>/report`. Секрет, если задан `reportSecret`, —
   в `NANO_TELEMETRY_SECRET`. Отправка вообще работает только у тех
   пользователей, кто сам включил «Отправку отчётов» в настройках.

## Безопасность

- **Используйте HTTPS.** Отчёты содержат имена плагинов и фрагменты
  декомпилированного кода; по голому HTTP их читает любой узел на пути.
  Поставьте перед сервером nginx/Caddy с сертификатом и слушайте
  `127.0.0.1`.
- Сервер ограничивает размер тела (25 МБ, в байтах), число запросов с одного
  IP, время на заголовки/тело и число одновременных обработок; кривой JSON
  возвращает `400`, а не роняет процесс.
- Имена файлов в отправляемом ZIP очищаются от `..` и абсолютных путей, но
  всё равно распаковывайте архив в отдельную пустую папку.
- Клиенту не возвращаются подробности ошибок Telegram (они пишутся только в
  лог сервера).

## Как узнать свой chat id

1. Написать созданному боту любое сообщение (просто открыть с ним чат и
   отправить "привет").
2. Открыть в браузере:
   `https://api.telegram.org/bot<TOKEN>/getUpdates`
3. В ответе найти `"chat":{"id": ЧИСЛО, ...}` — это и есть `chatId`.

## Держать сервер живым (по желанию)

Простейший вариант — `pm2` или systemd-юнит; для одного личного сервера
достаточно и `nohup node server.js &` / `screen`/`tmux`.
