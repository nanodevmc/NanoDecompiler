найденные при статическом разборе, и проверено сборкой и запуском (см. раздел «Как проверено»).
Подробный список изменений для пользователей — в `CHANGELOG.md` (раздел `2.0.0-alpha`).

## 2. Исправления по областям

### Утечки данных и приватность
- **Телеметрия** (`electron/main.ts`, `src/state/engine.tsx`, `src/lib/telemetry.ts`, UI/i18n/README/docs): см. таблицу выше.
- **Экспорт в GitHub** (`electron/pluginTools.ts`): токен больше не попадает в argv `git`, URL remote и `.git/config` (передаётся через `GIT_CONFIG_*` в окружении процесса); маскируется в сообщениях об ошибках; убран `push --force`; валидация токена/имени репозитория; путь с `~` теперь раскрывается (раньше экспорт для папки результата по умолчанию всегда падал).
- **Секреты в репозитории**: токены в коде не найдены. Служебные скрипты `scripts/*.py` брали PAT из `git config remote.origin.url` — теперь `scripts/_gh_auth.py` (переменная `GITHUB_TOKEN`/`GH_TOKEN` или `gh auth token`), с подсказкой отозвать токен, если он лежит в URL. `telemetry-server/config.json` (токен Telegram-бота) добавлен в `.gitignore`. **Проверьте историю git и отзовите токены, которые когда-либо лежали в `origin`.** `scripts/download_windows.py` больше не содержит имя пользователя и проверяет SHA-256.
- **Временные файлы**: распакованные архивы и скачанные установщики копились в `%TEMP%` — теперь удаляются сразу после обработки/при ошибке, устаревшие (>24 ч) подчищаются при старте (Electron и движок); каталоги создаются с правами 0700 и случайными именами.

### Выполнение команд / инъекции
- Новый `resources/engine_cpp/{include,src}/proc_util.*`: запуск программ **без shell** (`CreateProcessW` с корректным квотированием / `posix_spawn`), таймауты, лимит вывода, поиск исполняемых файлов **не в текущей директории**. Заменены все `std::system`/`popen`: `curl`, `7za`/`7z`/`unrar` (у `unrar` ещё и был неверный синтаксис), `apt-get` через `pkexec`, самообновление.
- `electron/main.ts`: «Открыть в…» (`apps:openWith`, `shell:openInVSCode`) больше не исполняет имена папок с `&`/`$()`; `where`/`which` без shell.
- `electron/archiveExtractor.ts`: `execSync("unzip …")` → `execFile` с массивом аргументов.

### Обновления
- `electron/updater.ts`: адрес из рендерера не принимается — берётся ассет последнего релиза репозитория; только https и GitHub (в т.ч. на редиректах, `Location` теперь разрешается относительно URL, лимит редиректов); SHA-256 обязателен для клиента **и** движка; приватный каталог 0700; запуск установщика без `.bat`; ограничения размера; закрытие дескрипторов и удаление недокачанного при обрыве/таймауте.
- `resources/engine_cpp/src/auto_update.cpp`: проверка HTTP-статуса, SHA-256 и размера, откат при сбое замены на Windows, `curl` без shell, атомарная замена рядом с exe, остатки (`.old`) подчищаются при следующем запуске.

### Недоверенные архивы и входные данные
- Общий безопасный читатель ZIP для Electron (`electron/zipReader.ts`, заменил три копии) и усиленный `zip_reader.cpp`: размеры сверяются с файлом, лимиты (zip-бомба: раньше `vector(4 ГиБ)` по заголовку в несколько байт), проверка чтения.
- `archive_extractor.cpp`: лимиты размера/числа файлов (в т.ч. предварительный `7z l -slt`), зарезервированные имена Windows, tar: GNU long names, PAX, base-256 размеры, ссылки не создаются, права на запуск из заголовка; при превышении лимитов встроенного ZIP-распаковщика внешний не запускается.
- `process_jar.cpp`: имя файла результата одиночного `.class` проходит через санитайзер путей (обратные слэши давали выход из каталога на Windows).
- `json_value.cpp`: ограничена глубина вложенности (иначе JSON из сети валил процесс переполнением стека), суррогатные пары.
- `legitimacy_check.cpp`: список разрешённых хостов (раньше удалённый `legitimacy_sites.json` мог направить движок на любой адрес), общий дедлайн 8 с теперь реально работает, хеш jar считается корректно при не-ASCII путях, ограничение размера HTML перед `std::regex`.
- Rust `fastscan`: лимиты на размер записей, без `unsafe`-mmap, паника не пересекает FFI, корректный JSON ошибок, разбор только верхнеуровневых ключей `plugin.yml`. Заодно исправлена сборка под `zip = "9.0"` (на текущем `main` крейт не компилировался: `entry.name()` в zip 9 возвращает `ZipResult`).

### Electron-оболочка
- `sandbox: true`, запрет навигации/попапов/webview, deny-by-default для разрешений; валидация аргументов всех IPC-хендлеров; фильтрация `settings:set`; атомарная запись настроек.
- Файловый проводник (`fs:*`, `search:inProject`): корень может быть только каталогом результата, который сам отдал на декомпиляцию `run:decompile` (раньше корень приходил из рендерера, т.е. защита была формальной), с учётом symlink'ов.
- `archive:cleanupTemp` (раньше удалял всё, где в пути есть «NanoDecompiler»), `shell:openPath` (не запускает исполняемые типы), `github:searchSimilar` (инъекция квалификаторов поиска из `plugin.yml`), `run:cancel`/процессы не остаются сиротами при закрытии окна, гонка `runningProc`.
- `tools:addToSystemPath`: сравнение по точному элементу PATH (раньше `-notlike` с wildcard-символами).

### Сервер телеметрии (`telemetry-server/server.js`)
- Один запрос с `null`/`heavy_files:[null]` больше не роняет процесс; лимит запросов по IP, таймауты, лимит тела в байтах, сравнение секрета за постоянное время, корректное усечение HTML для Telegram, очистка путей в ZIP, клиенту не возвращаются ошибки Telegram. README сервера обновлён.

### HTTP API движка (`api.cpp`)
- Невалидный `--host` больше не превращается в `0.0.0.0`; токен для не-loopback; проверка `Host`; корректный разбор `Content-Length` (раньше `std::stoul` бросал исключение в потоке → падение процесса), лимиты тела/соединений, таймаут чтения, полная отправка ответа, уникальные каталоги результата.

### Установщик JDK/Maven (`toolinstaller.cpp`)
- SHA-256 JDK из API Adoptium, SHA-512 Maven из независимого источника (новый `sha512.hpp`, сверен с эталоном), безопасная распаковка, права на запуск, таймаут 30 мин вместо 5 мин.

### Остальные ошибки
- Windows: резерв стека 64 МБ (`CMakeLists.txt`) — на `NanoMarket-2.0.0.jar` сборка без оптимизаций падала `0xC00000FD`.
- `--jar-summary` печатал невалидный JSON для путей Windows.
- `src_lite_cs`: **`MainWindow.axaml` и `MainWindow.axaml.cs` в теге целиком состояли из нулевых байтов** (Lite GUI не мог собраться) — восстановлены из `main`. Плюс: поиск движка в текущей папке/Загрузках/PATH с маской заменён точными именами; встроенный движок распаковывается в профиль пользователя и проверяется хешем (раньше — по размеру в общем `%TEMP%`); учитывается код возврата движка; stderr читается параллельно; `async void` не роняет приложение; сравнение версий с пре-релизами.
- CI: `contents: write` только у job публикации релиза; `afterPack.cjs` (символические ссылки, `.dSYM`).
- Исправлены устаревшие бейдж версии и тексты README; в `CMakeLists.txt` подключён `Threads`.

## 4. Что осталось (рекомендации, не менялось)

1. **Телеметрия по HTTP.** Адрес `http://195.179.231.14:15015` — открытый текст. Поставьте перед сервером TLS-прокси и задайте HTTPS-адрес.
2. **CSP для рендерера** не добавлялась (нужен ручной прогон интерфейса, иначе можно получить пустое окно); при желании — `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:`.
3. **Подпись релизов.** `checksums.json` лежит рядом с файлами, т.е. защищает от повреждений и подмены CDN, но не от компрометации аккаунта GitHub. Нужны подпись кода (Authenticode/Developer ID) или `cosign`.
4. **GitHub Actions**: сторонние действия (`softprops/action-gh-release`, `msys2/setup-msys2`) указаны по тегам — закрепите по SHA.
5. **Длинные пути Windows**: файлы глубже 260 символов движок открыть не может («не удалось проверить файл»). Нужен манифест `longPathAware` и/или префикс `\\?\`.
6. **Проверка легитимности** при включении может скачать до 100 ассетов по 50 МБ на кандидата — разумно ограничить суммарный трафик.
7. **Встроенные бинарники**: `7zip-bin` 5.x несёт `7za` 16.02 (старый); в `src_lite_cs/NanoDecompilerLite/Resources/NanoDecompilerCLI.exe` в репозитории лежит собранный бинарник, проверить который по исходникам нельзя — лучше класть его только в CI.
8. Комментарии в `version.hpp` (строки ~129–135) испорчены двойной перекодировкой (mojibake) — на работу не влияет.
9. Тег `v2.0.0-alpha` содержит зануленные файлы Lite GUI; стоит пересобрать/перевыпустить тег из исправленного коммита.
